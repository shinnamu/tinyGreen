# 창 배치는 곁가지 옵션이다

## 맥락

나무는 창을 Rectangle로 옮겨 왔고, 2026-10-23 Rectangle을 지웠다. 뜻은 「Rectangle 같은 건데 우리 것으로, 나와 Aside가 창을 자유자재로 다루는 것」이고, 자리는 tinyGreen이다 — tinyGreen은 하드웨어와 소프트웨어를 배선하는 곳이라서. 창을 옮기는 일은 정체 문장("입력 소스의 상태를 비춘다") 밖이라 ADR-0005의 판정으로 **곁가지**다. 이 ADR은 그 결정과, 기존 키 흐름에 어떻게 얹는지를 적는다.

## 결정

창 배치를 tinyGreen에 **곁가지로** 들인다. 정체 문장은 바뀌지 않는다 — 창 배치는 아무것도 비추지 않고, "거짓 비춤 없다" 약속을 지지 않는다.

ADR-0008의 기능 키처럼 **모드가 아니라 옵션**이다. 메뉴 「창 배치」 한 항목으로 켜고 끈다. 배포본은 **기본 꺼짐**, 나무 머신에서는 켜 둔다. 꺼져 있으면 tinyGreen은 창을 건드리지 않는다 — 단축키도 URL 스킴도 거절한다.

입구는 둘이다.

- **손 단축키 네 개** — ⌃⌘← 왼쪽 반, ⌃⌘→ 오른쪽 반, ⌃⌘F 채우기, ⌃⌘C 가운데. Rectangle 시절의 손버릇 그대로다. 나무 손이 이미 아는 키라 새로 익힐 게 없다. 편집 UI는 없고 `Settings`의 상수다.
- **URL 스킴 `tinygreen://place/<자리>`** — Aside가 부르는 입구. 자리 이름은 Rectangle의 동작 이름을 따른 열아홉 개(left-half … previous-display)다. 앞 앱의 포커스 창을 옮기므로, 부르는 쪽이 먼저 그 창에 포커스를 준다.

단축키는 Router의 기존 CGEventTap 안에서 받는다. ⌃⌘ + ←/→/F/C keyDown을, 옵션이 켜진 때만 소비하고 main으로 던져 놓는다. 버퍼·타이머가 없고 **tap mask는 keyDown 그대로**라 ADR-0001과 같은 길 위에 있다 — 소비한 keyDown의 짝 keyUp은 앱으로 흘러가고, 짝 없는 keyUp은 앱이 무시한다(🔍→F17과 같은 수용). 전환 키(F19/F18/F17) 분기와 Shift Lock 판정은 그대로다 — 창 단축키 분기는 F19 분기 뒤, Shift 끼얹기 앞에 따로 선다.

창은 손쉬운 사용 API(AXUIElement)로 옮긴다. tinyGreen이 이미 받는 손쉬운 사용 권한 하나로 충분해 새 권한이 없다.

## 결과

- 새 권한·새 외부 의존성 없음. 손쉬운 사용 권한이 없으면 창 배치는 로그 한 줄을 남기고 아무 일도 하지 않는다.
- ⌃⌘F는 여러 앱의 "전체 화면" 기본 단축키다. 옵션이 켜져 있으면 tinyGreen이 먼저 가져간다 — Rectangle 시절과 같다. 옵션을 끄면 앱에 그대로 간다.
- secure input 중에는 tap이 키를 못 받아 단축키가 걸리지 않는다(기존 한계와 같다). URL 스킴은 그때도 된다.
- 전체 화면 창은 건드리지 않는다. 세로 화면에서도 3분할은 가로로 자른다(Rectangle은 세로로 자른다) — 나무 머신엔 세로 화면이 없어 단순한 쪽을 골랐다.
- restore는 tinyGreen이 마지막으로 옮기기 전의 자리로 한 번 되돌린다. 기억은 메모리에만 있어 앱을 다시 띄우면 사라진다.
