# 기능 키 배선은 모드 밖의 옵션이다

## 맥락

나무 맥북 내장 키보드의 🎤(F5 자리)와 🔍(F4 자리)에 나무의 도구를 잇고 싶었다 — 🎤는 F18로 바꿔 Raycast 받아쓰기에, 🔍는 Aside 미니 팝업 단축키(⌃⌥A)에. 🎤 배선은 그동안 tinyGreen 밖(robots launchd의 hidutil 한 줄)에 살았다. 이 일은 정체 문장("입력 소스의 상태를 비춘다") 밖이라, ADR-0005의 판정으로 **곁가지**다. 2026-10-23 나무가 이 둘을 tinyGreen의 기능으로 묶기로 정했다. 같은 날 배치도 정했다 — 「f19 18 17이 비었네 이거 다 연결해」: F19 = 한영(그대로), F18 = 🎤, F17 = 🔍. 이 ADR은 그 결정과, 그 결정이 ADR-0004의 배선 단위를 어떻게 넓히는지를 적는다.

## 결정

두 키를 tinyGreen에 **곁가지로** 들인다. 정체 문장은 바뀌지 않는다 — 두 키는 아무것도 비추지 않고, "거짓 비춤 없다" 약속을 지지 않는다.

두 키는 **새 모드가 아니라 옵션**이다. 전환 키(Caps Lock / Right Command)와 직교해서 어느 모드에서든 하나씩 켜고 끈다. 그래서 배선의 단위를 넓힌다: 앱이 소유하는 배선 집합 = **모드 배선 ∪ 켜진 옵션 배선**. `apply`는 이 합집합을 여전히 **한 번의 hidutil set**으로 건다(ADR-0004의 원자성 유지). 물리 키의 신원은 전환 키 enum과 분리된 축(`ExtraKey`)으로 다룬다 — 전환 키 라디오에 기능 키가 섞이지 않게.

- 🎤 → F18: hidutil 배선만. 앱은 그 키를 소비하지 않는다.
- 🔍 → ⌃⌥A: hidutil로 빈 기능 키(F17)에 건 뒤, Router가 그 keyDown을 소비하고 그 자리에서 ⌃⌥A를 합성해 쏜다. 버퍼·타이머가 없고 tap mask는 keyDown 그대로라 ADR-0001과 같은 길 위에 있다.

옵션 배선에만 **인수** 규칙을 둔다: 같은 물리 키에 이미 우리와 똑같은 목적지의 매핑이 있으면 사용자 충돌로 stash하지 않고 우리 소유로 넘겨받는다. 모드 배선은 지금처럼 인수하지 않는다.

배포본에서 두 옵션은 **기본 꺼짐**이다. 받는 쪽엔 F18·⌃⌥A를 받을 도구가 없다.

## 결과

- GLOSSARY의 "곁가지 = 한 앱(= 전환 키 배선 하나)" 괄호는 더는 맞지 않아 "배선 집합 하나"로 고친다.
- Right Command 모드가 이미 F18을 대문자 잠금 방아쇠로 소유한다. 그래서 그 모드에서는 🎤 옵션이 배선에서 빠지고, 메뉴 항목은 이유를 단 채 비활성이 된다. 사용자가 켜 둔 값은 남아 Caps Lock 모드로 돌아오면 다시 걸린다.
- 옵션을 켜고 끄는 것도 모드 전환과 같은 길(조회 → 소유분 제거·원본 복원 → 충돌 stash → 추가 → set 한 번)을 탄다. stash는 옵션마다 슬롯이 하나씩 늘고, 크래시 뒤 정리를 위해 마지막으로 건 옵션 집합을 디스크에 남긴다.
- robots launchd의 🎤 배선은 tinyGreen이 같은 매핑을 인수한 뒤, 나무가 동작을 확인하고 나서 걷는다. 인수 덕에 걷은 뒤 주인 없는 매핑이 남지 않는다.
- 🔍는 secure input 중에 tap이 키를 못 받아 아무 일도 하지 않는다(기존 한계와 같다). "F1, F2 등을 표준 기능 키로 사용"을 켠 사람은 fn을 함께 눌러야 걸린다.
