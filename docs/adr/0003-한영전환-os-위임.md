# 한영 전환은 OS 일이다 — tinyGreen은 결과만 읽는다

## 맥락

옛 tinyGreen은 전환 키를 가로채 자기가 입력 소스를 바꿨다. 전환을 우리가 일으키니 그 결과의 타이밍도 우리 책임이 됐고, 그 위에 완화가 쌓였다 — 영어경유 더블탭·verify-retry·focusNudge, 그리고 KeyHoldGate. ADR-0001이 게이트를, ADR-0002가 라이브 계측을 각각 정리하고 나니 남은 물음은 하나였다: 우리가 전환을 계속 소유해야 하는가.

## 결정

전환을 OS에 넘긴다. hidutil이 전환 키를 F19로 바꾸고, `Router`는 plain F19를 **소비하지 않고 흘려보내며**, 사용자가 시스템 설정에 등록한 "입력 메뉴에서 다음 소스 선택" 단축키가 실제 전환을 한다. tinyGreen은 결과(보고된 상태)만 읽는다 — 완화 넷은 전환부와 함께 증발했다.

## 결과

- 앱 혼자 완결되지 않는다. 사용자가 시스템 단축키를 손수 F19로 등록해야 동작한다(README 사용 3단계). 대신 race 특성이 시스템 기본 한영 전환과 **같은 경로라 같아진다** — 우리가 더 일으키지도, 덜 일으키지도 않는다.
- 입력 소스가 셋 이상이면 토글이 시스템 목록 순서를 돈다. 옛 tinyGreen이 직접 전환하며 하던 영어 prefetch 보장은 사라졌다(README 알려진 한계).
- 읽기의 트리거가 옮겨갔다 — 키 가로채기(tap)가 아니라 OS의 변화 알림(monitor)이 읽기를 깨운다(`Watcher`). 운전석을 내려놓고 관찰석만 남았다.
