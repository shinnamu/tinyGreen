# 모드는 hidutil 배선 집합을 통째로 소유한다

## 맥락

전환 키가 Caps Lock 하나였을 땐 배선도 `Caps→F19` 하나였다. 메뉴에 Right Command를 선택지로 넣으며 "그럼 Caps Lock은?"이 남았다 — 그대로 시스템에 두면 native alpha-shift가 켜지고, 앱 소유 합성 Shift Lock과 나란히 **대문자 상태가 둘**이 된다.

## 결정

배선의 단위를 키 하나가 아니라 **모드 하나**로 잡는다. `Remap.ownedPairs(for:)`가 모드별 (물리 키 → 목적지) 집합을 소유한다: Caps Lock 모드 = `Caps→F19`, Right Command 모드 = `RCmd→F19` + `Caps→F18`. 두 모드 다 Caps를 시스템에 남기지 않으며, 대문자 잠금은 모드 무관 단일 합성 Shift Lock이고 모드가 바꾸는 건 방아쇠뿐이다(Shift+F19 / F18).

## 결과

- 대문자 상태가 하나뿐이다 — native alpha-shift는 아예 켜질 수 없다.
- 대신 매핑이 선 뒤엔 **켜져 있던 native Caps를 끌 키가 없다.** 그래서 매핑 적용·재배선 **전에** `NativeCapsLock.turnOffIfNeeded()`로 먼저 끄고, 실패하면 매핑을 적용하지 않는다(숨은 alpha-shift를 남기는 쪽이 더 나쁘다).
- 모드를 갈아탈 때 놓아주는 키의 사용자 원본 매핑을 복원하고 새 키의 충돌은 stash해야 한다. 배선이 집합 단위라 `apply`가 이 전부를 **한 번의 hidutil set**으로 한다 — 중간 상태를 밖에 노출하지 않는다.
